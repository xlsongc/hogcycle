# hogcycle

[English](README.md) · **中文**

猪周期的双时态数据仓库与看板。

线上：[English](https://xlsongc.github.io/hogcycle/) ·
**https://xlsongc.github.io/hogcycle/zh/**

## 为什么要有这个项目

这个项目需要的序列，`akshare` 大多一行就能取回来。所以有意思的问题不在「怎么抓」，
而在于：直接抓一次，拿到的是**今天这个版本的历史**；而整个周期里最重要的那个指标
——能繁母猪存栏——恰恰是会被事后修订的。

于是最该问的那个问题变得无法回答：

> 产能信号究竟有没有在价格动之前叫出拐点？而且只用当时能知道的数据。

对着一张会静默吸收修订的表，这个问题是验证不了的。所以这个库保留两条时间轴，
永不覆盖：

| 时间轴 | 字段 | 含义 |
| --- | --- | --- |
| 有效时间 | `obs_date` | 这个数字描述的日期 |
| 事务时间 | `fetched_at` | 我们知道它的时刻 |

`SilverStore.as_of(moment)` 由此可以重建任意历史时点上的「知识状态」。
仓库里其余的一切，都是为了让这个保证不掺水。

```
--- 2026-05-01 的知识 ---              --- 今天的知识 ---
  2025-12-31  4038.0                     2025-12-31  4038.0
  2026-03-31  3920.0                     2026-03-31  3904.0   <- 被修订
                                         2026-06-30  3780.0
```

每天都跑采集还有第二个更直白的理由，和修订无关：akshare 的**日频**序列只保留约
1 年的滚动窗口，更早的数据会从上游整个消失。断一年，那一年就在所有免费源里没了。

模块按**数据源与职责**切分，而不是按技术分层。每个源都有自己的失败方式、
自己的节奏和自己的口径；这些脏东西全部关在 bronze 与 silver 之间。
gold 层永远不知道某个数字来自哪个网站。

## 分层规则

**bronze** —— 原始载荷，逐字保存，不改不删。内容寻址，所以「今天没变化」这一天
只花一行 manifest、零字节载荷。它在解析**之前**写入，因此解析器的 bug 可以离线
修复：改解析器、重建 silver，不必重新抓取。昨天是抓不回来的。

**silver** —— 只追加。一次修订是老行旁边的**新行**，不是盖在老行上。
`append_changes()` 只写真正变化了的值。

**gold** —— 纯派生，几秒即可重建，因此不入版本库。它只做计算与对齐，不做判定。
这里没有任何规则会输出「我们正处在去化期」—— 可用历史约三轮周期，
任何这样的规则都会被自己的样本拟合。

## 使用

```bash
pip install -e "./backend[dev]"
cd backend && pytest -q

hogcycle collect              # 全部指标；单条失败不影响其余
hogcycle collect --months-back 60    # 回补农业农村部月度期次（默认 6）
hogcycle status               # 每条序列的覆盖度、最新 obs_date 与年龄
hogcycle status --fail-on-stale      # 有序列停止推进则退出码 1
hogcycle revisions --indicator sow_inventory
hogcycle export               # gold -> frontend/src/data/wall.json
hogcycle export --as-of 2026-01-01   # 重建那一天所见的图表墙

cd frontend && npm install && npm run dev
```

## 关于站点

两种语言，各自**预渲染成独立页面** —— 英文在 `/`，中文在 `/zh/`。
切换是一个链接而不是一个开关，这样每个版本都有可分享、可被收录的 URL，
并且它吐出来的 HTML 里 `lang` 属性是对的。指标名随契约同时携带两种语言，
因为**口径就写在名字里**，放一张前端查找表迟早会和它漂移。
详见 [ADR-0014](docs/adr/0014-the-site-speaks-two-languages.md)。

## 数据源与坑

价格与股票走 `akshare`，其上游是玄田数据 / 中国养猪网与行情宝 —— 是 JSON 接口，
不是爬 HTML。产能直接取自发布方：农业农村部生猪专题月度数据，由农业农村部、
发改委、商务部、海关总署、国家统计局联合发布，每月一期 XLSX。
本项目保持克制：每天只抓一次；读同一张表不同列的指标共用一次调用；
只重读很短一段尾部期次。

这个切分是踩出来的。能繁母猪存栏原先也走 akshare，而它的上游是同一份政府发布的
**镜像**——这个镜像 2025 年 10 月起停更，却继续供应最后那批行，于是采集器每天早上
照报成功，一连十一个月。现在 `hogcycle status --fail-on-stale` 会把
「停止推进的序列」当作失败。详见
[ADR-0013](docs/adr/0013-sow-inventory-moves-to-the-primary-source.md)。

以下这些坑，全部编码在 `sources.yaml` 里：

- **能繁母猪存栏在同一列里混了三种粒度。** 2009-2020 是年度值（一份冻结的第三方
  快照，从 bronze 回放 —— 已经没有活源还留着）；2021-12 至 2025-10 是月末值；
  2026 年起只发季度末，因为公开节奏变了。季度末是国家统计局调查数，
  月度值则由农业农村部定点监测的环比推算。可信度不同，却在同一列里 ——
  所以每一行自带 `granularity`，而对这条序列，粒度同时编码了口径。
- **定点屠宰量在 2025 年 7 月换了口径**（规模以上 → 全部定点企业），
  绝对值随之跳升。拆成两条指标，绝不接成一条；旧口径标记为 `retired`，
  它的缺席是预期之内，不是每天一次的失败。
- **正常保有量是移动基准**（4100 → 3900 → 3750 万头）。任何缺口或比值都必须用
  当期基准，不能用今天的。
- **生猪价格存在三套口径**（玄田全国均价、行情宝平台成交价、农业农村部 500 县
  集贸市场）。绝不画成一条线；每套自己成板。
- **玉米按元/吨报价**，不是元/公斤。量纲统一在 gold 层做，silver 层忠于源。
- **PSY 的提升会抵消母猪去化。** 母猪减 5% 不等于供给减 5%。
  任何「产能 → 供给」的模型都需要一个生产效率项，否则它会朝着最费钱的那个方向错。
